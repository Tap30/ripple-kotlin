# Publishing to Maven Central

This guide explains how to publish the Ripple Kotlin SDK to Maven Central.

## Project Publishing Setup

The Maven group and version are configured globally in `build.gradle.kts`:

```kotlin
group = "cab.tapsi.oss"
version = property("VERSION_NAME") as String
```

`VERSION_NAME` in `gradle.properties` is the default version for local builds and manual publishing. The GitHub release workflow derives the Maven version from the pushed tag and passes it to Gradle as `ORG_GRADLE_PROJECT_VERSION_NAME`.

Publishable modules apply either `publishing-convention` or `android-publishing-convention` from `build-logic`:

- JVM/Kotlin modules publish from `components["java"]` with sources and javadocs jars.
- The Room adapter publishes the Android `release` variant from `components["release"]`.
- Sample modules are not published.

Artifact IDs are generated by convention:

- Top-level platform modules use `ripple-{project-name}`, for example `ripple-core`, `ripple-android-core`, `ripple-spring-core`, and `ripple-reactive-core`.
- Adapter modules use `ripple-{platform}-adapters-{name}`, for example `ripple-android-adapters-okhttp` and `ripple-spring-adapters-webflux`.

Published artifacts use one Maven publication named `maven`.

Configured publish targets:

- Maven Central/Sonatype: configured through the root `nexusPublishing` block.
- GitHub Packages: `https://maven.pkg.github.com/Tap30/ripple-kotlin`
- Tapsi Artifactory: `https://artifactory.tapsi.tech/artifactory/tap30-release`

## Prerequisites

### 1. Create Sonatype Central Portal Account

1. **Sign up for Central Portal:**
   - Go to [Central Portal](https://central.sonatype.com/)
   - Create an account with your email

2. **Register and verify namespace ownership:**
   - Namespace: `cab.tapsi.oss`
   - Project URL: `https://github.com/Tap30/ripple-kotlin`
   - SCM URL: `https://github.com/Tap30/ripple-kotlin.git`

3. **Generate a Central Portal user token:**
   - Use the generated username/password token pair for publishing.

### 2. Generate GPG Key for Signing

```bash
# Generate GPG key
gpg --gen-key
# Follow prompts: use your email, set a passphrase

# List keys to get the key ID (last 8 characters)
gpg --list-secret-keys --keyid-format LONG

# Export public key and upload to key servers
gpg --armor --export YOUR_KEY_ID > public-key.asc
gpg --keyserver keyserver.ubuntu.com --send-keys YOUR_KEY_ID
gpg --keyserver keys.openpgp.org --send-keys YOUR_KEY_ID

# Export secret key for GitHub Actions
gpg --armor --export-secret-keys YOUR_KEY_ID > private-key.asc
```

### 3. Set Up Local Credentials

Create `~/.gradle/gradle.properties`:

```properties
# Central Portal token credentials
centralPortalUsername=your_token_username
centralPortalPassword=your_token_password

# GPG signing, ASCII-armored private key
signingInMemoryKey=-----BEGIN PGP PRIVATE KEY BLOCK-----...
signing.password=your_gpg_passphrase
```

### 4. GitHub Repository Secrets

Add these secrets in GitHub: **Settings → Secrets and variables → Actions**

- `CENTRAL_PORTAL_USERNAME`: Your Central Portal token username
- `CENTRAL_PORTAL_PASSWORD`: Your Central Portal token password
- `SIGNING_KEY`: ASCII-armored private GPG key
- `SIGNING_PASSWORD`: Your GPG key passphrase

To export the private key:
```bash
gpg --armor --export-secret-keys YOUR_KEY_ID
```

## Publishing Process

### Automated Publishing (Recommended)

1. **Create and push a version tag:**
   ```bash
   git tag v2.0.0
   git push origin v2.0.0
   ```

2. **GitHub Actions automatically:**
   - Runs all tests
   - Builds all artifacts
   - Uses the tag as the Maven version (`v2.0.0` publishes version `2.0.0`)
   - Signs with GPG
   - Publishes to GitHub Packages
   - Publishes through the Central Portal OSSRH Staging API
   - Releases to public Maven Central
   - Creates GitHub release

The release workflow runs:

```bash
ORG_GRADLE_PROJECT_VERSION_NAME=2.0.0 ./gradlew build --no-daemon
ORG_GRADLE_PROJECT_VERSION_NAME=2.0.0 ./gradlew publishMavenPublicationToGitHubPackagesRepository --no-daemon
ORG_GRADLE_PROJECT_VERSION_NAME=2.0.0 ./gradlew publishToSonatype closeAndReleaseSonatypeStagingRepository --no-daemon
```

### Manual Publishing

```bash
# Build and test before publishing
ORG_GRADLE_PROJECT_VERSION_NAME=2.0.0 ./gradlew build

# Publish all Maven publications to Sonatype staging
ORG_GRADLE_PROJECT_VERSION_NAME=2.0.0 ./gradlew publishToSonatype

# Close and release the staging repository to Maven Central
ORG_GRADLE_PROJECT_VERSION_NAME=2.0.0 ./gradlew closeAndReleaseSonatypeStagingRepository
```

To publish to local Maven for verification:

```bash
./gradlew publishToMavenLocal
```

To publish to GitHub Packages:

```bash
./gradlew publishMavenPublicationToGitHubPackagesRepository
```

To publish to Tapsi Artifactory:

```bash
./gradlew publishMavenPublicationToTapsiArtifactoryRepository
```

## Usage for Consumers

Once published, users can add dependencies:

```kotlin

implementation("cab.tapsi.oss:ripple-core:2.0.0")

// Android module  
implementation("cab.tapsi.oss:ripple-android-core:2.0.0")
```

## Troubleshooting

### Common Issues

1. **"Unauthorized" error:**
   - Verify Central Portal token credentials are correct
   - Ensure your account has access to `cab.tapsi.oss` group

2. **GPG signing fails:**
   - Check GPG key hasn't expired: `gpg --list-keys`
   - Verify passphrase is correct
   - Ensure key is uploaded to key servers

3. **Staging repository not found:**
   - Wait a few minutes after publishing
   - Check [Central Portal deployments](https://central.sonatype.com/publishing/deployments)

4. **Version already exists:**
   - Maven Central doesn't allow overwriting versions
   - Create a new version tag, for example `v2.0.1`
   - For manual publishing, pass the same version with `ORG_GRADLE_PROJECT_VERSION_NAME`
